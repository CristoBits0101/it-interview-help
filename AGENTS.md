# IT Interview Help — instrucciones para agentes

## Alcance y stack

- Mantén una aplicación estática de preparación de entrevistas técnicas con Astro, TypeScript estricto y CSS. No amplíes el producto a un currículo exhaustivo, SaaS o aplicación de escritorio.
- Conserva el stack salvo evidencia concreta y autorización de un cambio de alcance. No añadas React, backend, bases de datos, analítica, servicios de IA ni dependencias Python para presentar contenido educativo. La ciencia de datos del catálogo no exige infraestructura de ciencia de datos.
- Limita cada intervención a lo solicitado. Añadir contenido o reorganizar archivos no autoriza rediseñar contenedores, botones, tipografías, espaciado o animaciones. Conserva el contenido, diseño y comportamiento aprobados. Explica y consulta cambios ajenos al alcance antes de aplicarlos.
- Mantén este archivo como instrucciones concisas por áreas. No añadas fechas, diarios, resultados de pruebas ni manuales dirigidos al usuario. No crees otra memoria para trasladar aquí el exceso de documentación. Conserva las auditorías históricas útiles sin presentarlas como verificación actual.

## Trabajo en el repositorio

- Trabaja exclusivamente en `C:\Workspace\it-interview-help`, rama `main`. Verifica carpeta, `git symbolic-ref --short HEAD` y `git status` antes de editar. No crees ramas, worktrees ni copias auxiliares sin revocación expresa de esta regla.
- Conserva cambios ajenos, archivos pendientes e historial. No uses resets destructivos ni borres worktrees manualmente. Las barreras de `.codex/config.toml` y `.codex/rules/main-only.rules` son parciales; no sustituyen esta instrucción ni autorizan cambiar configuración global.
- Mantén disponible `http://localhost:4321/`. Reutiliza el servidor habitual y no detengas servidores ajenos. Usa un puerto libre para preview cuando sea necesario y retira solo tus procesos temporales.
- No hagas commit, push ni publicación en Sites por una revisión local. GitHub y Sites son destinos distintos. No apagues el ordenador. Una entrega remota requiere autorización explícita vigente.
- Edita fuentes en `src/`, recursos en `public/` y configuración pertinente. No edites `dist/` como fuente ni copies `index.astro` o `app.ts` a la raíz.
- No añadas comentarios de línea, bloque, JSDoc o HTML al código, scripts o configuración. Usa nombres claros, tipos y responsabilidades pequeñas.

## Arquitectura y convenciones

- Usa Screaming Architecture en `src/features/` con la misma jerarquía de etiquetas canónicas del sidebar. Cada dominio reúne sus componentes, datos, reglas, scripts y estilos. Home es un dominio propio; `src/app/` compone la aplicación y `src/shared/` contiene elementos transversales. Cada directorio de agrupación contiene solo subcarpetas y cada carpeta final solo archivos; `src/pages/` conserva las convenciones de rutas de Astro. Evita carpetas comodín, envoltorios y capas sin una responsabilidad concreta.
- Usa `src/pages/index.astro` para composición y `src/layouts/AppLayout.astro` para documento, metadatos y marco común. Reutiliza componentes de sus dominios en `src/features/` y elementos transversales de `src/shared/components/` con propiedades tipadas y datos como parámetros.
- Importa `AppLayout` antes de los componentes de página para establecer las capas CSS en orden `reset`, `base`, `layout`, `components`, `responsive`. Una reorganización de archivos conserva ese orden y los estilos existentes.
- Configura disponibilidad en `src/app/data/published-catalog.ts`. Conserva el contenido propio en su rama de `src/features/` y los agregadores de navegación y disponibilidad en `src/app/data/`; deriva inventarios y contadores, sin fijarlos a mano.
- Conserva las reglas, datos, scripts y estilos específicos dentro de su dominio en `src/features/`. Reserva `src/shared/` para elementos transversales con consumidores reales; no traslades allí contenido de negocio para acortar rutas. `src/app/scripts/app.ts` coordina y delega navegación, panel móvil, tarjetas, Home y diálogos. No crees archivos monolíticos ni abstracciones sin consumidores.
- Conserva IDs, hashes, clases, atributos `data-*`, contratos ARIA y claves persistidas. Antes de cambiar marcado o selectores localiza sus consumidores. Retira código solo cuando su falta de uso esté comprobada; conserva material histórico y soporte de repaso solicitado.
- Usa `PascalCase.astro` para componentes, `kebab-case` para archivos TypeScript/CSS/scripts y clases CSS, `PascalCase` para tipos y `camelCase` para funciones y variables. Respeta excepciones y nombres públicos existentes; evita renombres cosméticos masivos.
- Sigue `.editorconfig`: UTF-8, LF, dos espacios y salto final. Conserva la indentación del Java embebido. No dupliques implementaciones o diccionarios para el build y el navegador.

## Interfaz, tokens y accesibilidad

- Conserva la marca `IT Interview Help` sin icono ni puntuación. Marca y Home llevan a la portada real. No recuperes Library, marcadores, hero antiguo, repaso global ni pies retirados.
- Centraliza paleta, fuentes, radios y espaciado en `src/shared/styles/tokens.css`. Fuera de tokens usa variables, `currentColor`, transparencia o mezclas derivadas; no introduzcas colores literales ni acentos ajenos.
- Para futuros diseños toma Home como referencia de radios: prefiere 2XL en tarjetas y contenedores principales mediante `--radius-profile` (1rem, 16 px de base), y radio completo mediante `--radius-full` en selecciones, píldoras, chips y controles circulares según su función.
- Conserva la jerarquía interior de radios menores (`--radius-card`, `--radius-control`, `--radius-inset`) y radios concéntricos; no apliques redondeado universal ni cambies controles rectangulares o radios existentes sin petición.
- Usa Google Sans Flex para interfaz y encabezados. Reserva IBM Plex Mono para marca, títulos expresamente aprobados de categorías y Home y código mediante `--brand`/`--code`. Conserva la escala 13/14/15 px con pesos 300/400/500 y marca de 20 px/500 en unidades adaptables.
- Toma la jerarquía tipográfica real de Home como referencia por función: cabeceras de página y secciones decoradas en IBM Plex Mono 15 px/500, introducción y prosa en Google Sans Flex 13 px/300 y controles de texto en Google Sans Flex 14 px/400. Reutiliza `PageHeading`, `.section-title` y tokens. Distingue los títulos de tarjetas de Home por función (puestos mono 13 px/500, áreas 14 px/500 y categorías 15 px/500); no traslades sus variantes a toda tarjeta ni rediseñes páginas aprobadas. Conserva las excepciones Dancing Script de Home y Redaction 20/Dancing Script del 404. Consulta los roles y tokens en [Referencia tipográfica](docs/PROJECT_GUIDE.md#referencia-tipográfica-vigente).
- Mantén `--line-body: 1rem` compartido en toda la interfaz, incluido código, escalable con la raíz y compatible con preferencias de espaciado.
- Conserva padding exterior responsive y pares padding/gap de tokens. En Home usa `--space-home: 21px` solo para separaciones estructurales verticales y ambos lados de separadores; evita sumar márgenes y padding. Mantén compactos interiores y espacios horizontales.
- Usa Home como referencia de separación vertical entre bloques en todas las páginas mediante `--space-section: 21px` y `.page-flow`; `--space-home` comparte ese valor. Reutiliza `PageHeading.astro` para título e introducción y `.section-title` para el decorador común. Toma las tarjetas de Creational como referencia de proporción interior y conserva los pares padding/gap también en horizontal con múltiplos y mitades enteros en la escala base. Cada intervalo tiene un único responsable; calcula el espacio efectivo incluyendo márgenes, padding, gap e interlineado y evita acumulaciones involuntarias. Conserva separadores simétricos y reflujo accesible.
- Usa `--gap-horizontal`, ligado al padding compacto de selección (8 px de base y 4 px en el tramo compacto de Home), para la separación exterior entre componentes hermanos, incluidas áreas, puestos, etapas y Amplía tu Alcance. Conserva 21 px entre bloques y 10.5 px dentro del plan de etapa. Excluye el aside y los interiores de botones, chips, iconos y grupos de desplazamiento. Evita sumar márgenes al gap; los carruseles calculan sus anchos con el mismo gap horizontal y en áreas lo comparten también los espacios exteriores junto a las flechas, sin inset añadido en el viewport. Alinea el objetivo del plan con la primera fila de tarjetas mediante filas de rejilla compartidas, sin offsets basados en la altura del texto.
- Conserva justificación, última línea al inicio y palabras sin cortes en descripciones y prosa de Home. Permite reflujo con texto ampliado; no ocultes overflow para encubrir errores ni recortes contenido.
- En carruseles comprueba que el viewport no recorte bordes ni esquinas del primer y último elemento tras desplazar, redimensionar o ampliar texto. Los anchos fraccionarios pueden superar el límite de scroll redondeado por el navegador; distribuye el redondeo entre columnas mediante diferencias de límites acumulados redondeados para conservar el ancho total y los gaps. No encubras el recorte con overflow ni añadas inset al viewport de áreas.
- Usa exclusivamente Lucide mediante `Icon.astro`. Genera el favicon con el alias `brand`/CodeXml en `src/pages/favicon.svg.ts` y tokens; no dibujes iconos propios ni añadas un favicon manual.
- En el cuerpo de una página usa iconos distintos para encabezados de secciones visibles. Permite repetición funcional en listados, tarjetas equivalentes, elementos repetidos y controles recurrentes; no apliques esta unicidad al aside, a la navegación ni a variantes de paneles ocultas.
- Conserva el sidebar de filas de 48 px, inset horizontal de 18 px y chevrons alineados. Etiquetas completas en una línea, ancho intrínseco recalculado con idioma/fuentes/texto y scroll del aside a toda altura. Mantén la cobertura opaca sticky de la cabecera.
- Mantén el panel móvil a 850 px o cuando el sidebar deje menos de 20 rem al contenido. Conserva backdrop, `inert`, cierre con Escape y retorno del foco. Permite scroll horizontal interno del menú sin elipsis ni desbordamiento de página.
- Conserva navegación activa por color, peso y `aria-current`, sin fondos ni subrayado. No resaltes ramas ajenas por abrirlas. Breadcrumb desde Home con jerarquía completa, Title Case y peso normal también en la hoja actual.
- Mantén el buscador redondeado, tamaño de 14 px, foco suave y atajo Ctrl/Cmd + K sin etiqueta visible del atajo. Conserva el filtro de niveles con flechas, objetivo de 40 px y círculo/icono centrados; incluye solo niveles presentes y desactiva extremos.
- En estudio conserva contador y niveles bajo la cabecera compartida con título e introducción del módulo. Las cabeceras de página y los títulos de sección decorados usan mono 15 px/500, mayúsculas, borde izquierdo de 2 px y padding horizontal de 12 px mediante tokens comunes.
- Conserva tarjetas de igual altura, padding uniforme responsive, separadores completos y hover solo de borde. En los 14 patrones el número no lleva círculo y usa punto Lucide con espacios simétricos; título y autor quedan alineados. SOLID y glosario conservan su círculo.
- Mantén selector de vistas agrupado, radios concéntricos y controles amplios según CSS vigente. `Lo entiendo` permanece a la derecha, sin superficie exterior y con check circular. Conserva reflujo del pie, objetivos táctiles, fuente obligatoria y alineaciones; no partas palabras de botones.
- Usa movimiento breve con duraciones y easing compartidos para desplazamientos programáticos y cambios de estado apropiados. No interceptes el scroll manual ni uses autoplay, transiciones de todas las propiedades o animaciones de layout. Respeta movimiento reducido y conserva el selector de vistas seleccionado sin hover ni transición.
- Aplica WCAG 2.2 AA como objetivo: foco visible, contraste, nombres accesibles, teclado, reflujo, texto al 200 %, espaciado personalizado, movimiento reducido y colores forzados. No atribuyas efectos universales de aprendizaje a la paleta ni afirmes certificación por pruebas automáticas.

Las preguntas subordinadas de Introducción al JDK reutilizan el rol manuscrito de preguntas de Home y no llevan separadores propios. Conserva niveles HTML coherentes y las variantes aprobadas de tarjetas y preguntas interactivas; no impongas una fuente solo por usar `h2` o `h3`.

Destaca la base mínima esencial de las áreas relevantes para cada puesto. No lo presentes como curso exhaustivo ni garantía de éxito. Atribuye conceptos o preguntas a entrevistas y pruebas reales solo con evidencia verificable; expresa futuras ampliaciones como futuras y no modifiques catálogos por un ajuste de introducción.
- Conserva el árbol de `src/app/data/navigation.ts`, sus etiquetas canónicas y sus relaciones. Todas las ramas con hijos son desplegables; hojas sin contenido permanecen visibles, deshabilitadas y sin enlaces. No restaures el filtro Producción/Desarrollo.

Conserva disciplinas como Data Engineering, Data Science e IT Support. Mantén Distributed Systems separado de System Design y estilos separados de patrones arquitectónicos. ## Persistencia y seguridad

- Usa `src/shared/lib/preferences.ts` y conserva las cuatro claves: `tech-training:v1` para `{learned: [...]}`, `tech-training:navigation:v1` para ramas, `tech-training:language:v1` para ES/EN y `tech-training:career-stage:v1` para ID o JSON `null` sin etapa seleccionada. El roadmap de Home solo se muestra con una etapa seleccionada y se oculta al desmarcarla o deseleccionar sus controles superiores.
- Exceptúa únicamente la lectura del idioma existente para localizar la solicitud. Antes de leer o escribir las demás preferencias exige una decisión explícita en `tech-training:storage-consent:v1` con valor `accepted` o `rejected`. Sin decisión válida pregunta mediante el diálogo accesible; cerrar no consiente. Rechazar recuerda únicamente esa decisión y elimina solo claves propias de preferencias en localStorage/sessionStorage. No uses history ni otro almacén para eludir el modo memoria. Aceptar inicialmente puede restaurar datos anteriores; reactivar desde Preferencias guarda el estado actual. Conserva la clave de sonido `tech-training:sound:v1` y el retorno de sesión `tech-training:last-route:v1` bajo el mismo control. Sin idioma válido disponible usa inglés. El sonido está desactivado sin consentimiento.
- El diálogo de guardado usa tarjeta 2XL (`--radius-profile`), dos acciones centradas con radio completo y ningún botón X. Escape continúa sin guardar ni registrar decisión. La acción de guardar parte de fondo transparente y texto del color de su borde; conserva foco visible, teclado, reflujo y colores forzados.
- Valida formas e IDs, ignora datos corruptos sin bloquear el arranque y tolera getter, lectura, cuota o escritura fallidos. Mantén estado en memoria y permite recuperación de escrituras posteriores. No confundas corrupción de JSON con indisponibilidad permanente.
- Conserva migraciones en `navigation-migrations.ts`, hijos abiertos dentro de padres cerrados y restauración tras recarga/idioma. Nunca abras ramas automáticamente al navegar. La búsqueda puede abrir coincidencias y ancestros solo temporalmente sin guardar esos cambios; al limpiarla restaura la expansión previa. El área y el perfil son de sesión; etapa, idioma, progreso y ramas se guardan localmente.
- No introduzcas cookies, seguimiento o sincronización remota. Las preferencias pertenecen al origen y navegador; no prometas recuperación si se borran. No almacenes secretos ni datos personales y no limpies almacenamiento ajeno.
- Inserta contenido mediante texto/nodos y escape de Astro; no añadas HTML sin sanitizar, `eval` ni ejecución de los ejemplos. Valida URLs HTTPS y conserva `noopener noreferrer` en enlaces externos.
- Mantén CSP en `astro.config.mjs` sin `unsafe-inline`/`unsafe-eval` y verifica el build con preview. Comprueba compatibilidad con recursos del alojamiento antes de publicar. No presentes HSTS, `frame-ancestors`, compresión o caché HTTP como configurados por el manifiesto local; dependen del proveedor y deben verificarse allí.
- Todo recurso generado para el navegador es público. No publiques credenciales, `.env`, `node_modules`, `.astro`, `.sites-runtime`, mapas de fuentes, fixtures de QA ni capturas. No añadas archivos de cabeceras suponiendo soporte del alojamiento.

- Mantén en el README el inventario completo de páginas existentes entre «Rutas de producción estables» y «Rutas de desarrollo sujetas a cambios». Deriva las rutas del catálogo y las entradas Astro al añadirlas o cambiarlas; no incluyas hojas sin página ni deduzcas publicación de un push.

Publica únicamente con autorización mediante el flujo vigente de Sites; su helper de fuente puede hacer commit/push. Conserva versión/fuente validada para recuperación y usa herramientas del proveedor autorizadas, sin reset destructivo del trabajo pendiente.
